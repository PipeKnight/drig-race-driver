# Ground-placement prototype and remaining fidelity checks

Recorded 7 October 2026. `grid-world::spawn` now implements a bounded four-wheel ground-placement prototype. It combines the verified [wheel layout](WHEEL_GEOMETRY.md), [car collision bounds](CAR_COLLISION.md) and [grid rectangle](PROGRESS_AND_SPAWN.md). It is not yet the viewer's placement path and does not simulate suspension or driving.

## Recovered behavior

For original grid alignment mode one, center starts at the rectangle center. Longitudinal displacement is half the rectangle length minus the car's front extent; front extent is the collision mesh's maximum local Z plus wheel-layout offset Z. Explicit lateral displacement follows the rectangle's transverse edge. Original random lateral selection is a separate branch. The prototype CLI rejects cases requiring that branch; all 21 observed Donington markers permit zero lateral displacement for both reference cars. Deformation-adjusted extents and alignment modes two/three remain unsupported.

Ground/frame function `0x009de4e0` first takes the minimum of wheel base Y minus geometric radius, then negates that minimum to obtain the initial lift. A center cast descends from Y=10000 to -2000. Four more casts sample the corners of the wheel-span rectangle, using horizontal heading and its perpendicular. Their paired height differences determine longitudinal/lateral gradients; the up candidate combines those gradients with world Y=2. Corner misses use the center height. The original has a prior-pose fallback if the center cast misses; our supported prototype reports that case as unsupported.

For the supported up-Y >0.5 branch, initial vertical position is center ground height plus up-Y times lift, followed by `(up-X²+up-Z²)/up-Y` times lift. Side is normalized `cross(up, normalized desired heading)`, and forward is `cross(side, up)`.

The ordered pass visits rear positive-X, rear negative-X, front positive-X, front negative-X. It adds the wheel's current Y displacement, subtracts its initialized `.ned` radius, then transforms that local bottom point by the pose. The cast starts 0.5 above its world Y. Wrapper `0x009adc00` descends to **-10000**, unlike the initial center/corner casts. A hit raises pose Y if the bottom is below hit-height +0.005. Later wheel casts use the already-raised pose. This order is observable on layered surfaces. The CLI uses zero wheel displacement; live suspension displacements are separate state.

## Numeric and observation limits

The default prototype uses standard f32 square-root normalization and the independent f64 track BVH for height queries. An explicit `Normalization::ReferenceSse` option now uses the inspected reciprocal-square-root seed and refinement on x86 with SSE support. Unsupported platforms return an error. Reference-mode reports also reconstruct height from a f32 segment fraction. Original filtering, candidate traversal/tie selection, initialization-boundary state and suspension are not proved equivalent by this implementation. Near-vertical/zero-heading/center-miss fallback branches are deliberately unsupported.

Two source/native car reports produce 42 placements and 378 cast records. The first independent source-triangle comparison matches all 378 height words and validates orthonormal output frames. Its limited player comparison against the saved post-start state differs by about 0.002735 horizontally and -0.006021 vertically in source coordinates; the largest basis-component difference is about 0.002456. These are measured differences, not an acceptance threshold or a handling-fidelity claim. The snapshot was taken after a restart and roughly twelve seconds of simulation.

During call-graph auditing, the first prototype was found to use -2000 for the final wheel casts too. Corrected it to the wrapper's actual -10000 and retained the first run. The corrected v2 reports and fresh source comparisons supersede the original for this contract. Original evidence: `local/behavior/20261006T1407232213170Z/9adc00.c.txt`, `20261006T1546156162090Z/9de4e0.c.txt`, `spawn-prototype-call-instructions.json`. The instruction diagnostic includes bytes beyond the target function; only the identified function boundary is relevant.

Three analytic tests cover flat/slope placement, corner misses, ordered cast origins, invalid directions/radii/hits and explicit center-miss rejection. **43 format tests and ten world tests pass (53 total)** before final lint. An assign-operation lint was corrected; subsequent lint results are recorded in the project log.

## Controlled original arithmetic comparison (F061)

`tools/probe_ground_placement.c` runs only the inspected placement routine and numeric helpers in a hash-guarded private mapped analysis PE. It never runs its entry point, imports, TLS or constructors, and does not inject into the live game. Only the ground candidate collector is redirected in this isolated mapping to our analytic plane oracle. The original height adapter remains intact. Temporary patch pages are writable then restored to executable; the normalizer's constants page is writable data. Private images, executable, requests and result words remain under ignored `local/`.

`tools/validate_ground_placement.py` compares two analytic, 120 deterministic synthetic and eight source-derived Lacetti/BMW wheel cases: **130/130 reference-mode matrices and all 2,080 f32 words match bit for bit**. The first implementation matched 84 matrices; instruction review corrected transform grouping to `(translation + up*Y) + (side*X + forward*Z)`. Original and failed results are retained. Standard normalization with fractional heights matches no complete matrices, despite errors of only about 2.38e-7 in basis and 1.91e-6 in position. Direct plane heights produce larger differences. This demonstrates why an approximate numerical agreement is insufficient for the recovered contract.

Exactness is conditional on the oracle, supported branches and observed numeric environment: MXCSR `00001f80`, x87 control `0009001f`, mapped base `02140000`. Existing MSVC 14.44.35207 / SDK 10.0.26100.0 / VS tools prompt 17.14.41 were reused with `/fp:strict /arch:SSE2`; no installation. Rust is pinned to 1.99.0. Build, hashes and full comparisons: `local/behavior/isolated-ground-placement-validation-v2/validation.json`; previous run: `isolated-ground-placement-validation/`.

The unchanged private PE mapper is shared with the triangle probe in `tools/isolated_reference.h`. Rebuilding that probe preserves all **568 prior result rows exactly** (`triangle-shared-mapper-validation.json`). An initial invocation used a nonexistent `input.tsv` and exited before executing a case; rerunning with the actual `cases.tsv` succeeded.

Latest terrain reports use `grid-spawn GAME_ROOT CAR_ID local/OUTPUT.tsv reference`. All 42 placements and 378 query-height words agree with independent source-triangle/fraction reconstruction in `local/behavior/spawn-reference-arithmetic-validation/validation.json`. Against the historical post-start player state, horizontal distance is 0.00273538, vertical difference -0.00621891 and maximum basis difference 0.00219726. The source BVH remains an independent f64 candidate selector; this is not original whole-query equivalence. The validator's older generic limits string predates the conditional arithmetic comparison; the scopes above distinguish these results.

Final workspace tests (43 format + ten world), warnings-denied Clippy and native build pass: `placement-final-tests.txt`, `placement-final-clippy.txt`.
