## Runtime connection still required

Original wrapper `A727A0` dispatches every occupied transient contact in order before clearing its count, then separately handles persistent contact chains. The current owned world has only the transient pool. Wheel contacts also use the registered body shape; their relative points are converted to world points before solving by the existing contact-group builder. A runtime connection must include those contacts, preserve the active count separately from stable reusable capacity, use solved impulse writeback, publish the changed owner/frame prefix consistently, and roll back the entire tick on callback failure. Persistent chains, arbitrary notification implementations, dynamic other-car response and full asynchronous scheduling remain outside this scope.
