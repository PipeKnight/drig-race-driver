## Source sun vector traced — 18 October 2026

A static executable-section scan identifies the direct dispatcher caller at 0x735675. Aligned instruction decoding around it shows the temporary render context at stack+0x40: lighting-object+0x20/+0x28 are copied into context+0x10/+0x18, while object pointer is put at context+0x0C. Stack pushes/additions are accounted for: the first copy is stack+0x58 before add esp,8, hence final stack+0x50. No XYZ negation occurs in these copies. The dispatcher 0x743220 reads context+0x10, preserves XYZ using masks at 0xCAF430 (W-only) / 0xCAF460 (all bits), zeros W and submits the name at 0xCF3108 = sunDirection.

This connects the previously emulated matrix's third basis vector to the examined source shader uniform. For saved Donington angles its XYZ is approximately (0.2309974, 0.5750054, 0.7848624). Source track-infield pixel shader uses saturate(dot(normal, sunDirection)), confirming the vector points towards the light for diffuse shading. Static selected-path evidence is not a live runtime capture or a proof of all weather modes. Bevy's directional light emits along local -Z, so an adaptation must aim it opposite that vector, retaining our independent radiometry/exposure. No change to the default light has been made yet.

## Colour packing/scale traced — 18 October 2026

Do not multiply the saved HDR sun colour by the separately saved sunscale blindly. XML binding at72BC4F..72BC5A targets object+1B0 (backlight_suncolour), scalar binding72BCAA targets+304. Later XML completion72C21C..72C247 calls742B00 with the parsed colour and pointers to the packed-colour destination/+304, then stores the packed result at+2F8. The helper overwrites scale with max(1,R,G,B) and packs truncated8bit RGB/scale with alpha255. The lighting calculation730F90 reconstructs+1B0 from packed+2F8 and scale+304. Thus the saved HDR colour and saved scale are not two independent intensity multipliers in this examined path.
