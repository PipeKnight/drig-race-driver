## 3. Порядок действий

### Шаг 0. Заморозка — владелец

1. Владелец объявляет перенос Claude и Codex.
2. **Claude:** новых сессий не запускает. Ждёт, пока текущие сессии закончат и отправят работу в `main`, затем архивирует их. Незаконченные останавливает в чистом состоянии: всё закоммичено и отправлено в ветку.
3. **Codex:** коммитит и отправляет `codex/grid-graphics`, затем останавливается. Решает, что делать с локальной веткой `codex/f269-timed-lap-draft` (черновик F269 из stash): забрать, отправить на GitHub или оставить. Строки G001/G002 в рабочей копии `PROJECT_LOG.md` основной папки — тоже его решение: закоммитить в своей ветке или оставить незакоммиченными, они переедут вместе с папкой.
4. Владелец ставит синхронизацию OneDrive на паузу (значок в трее → «Приостановить синхронизацию» → 24 часа) и закрывает игру и прототип.

### Шаг 1. Проверка перед переносом — Claude

- `git worktree list`, затем `git status` во всех worktree. Незакоммиченное есть только там, где владелец сознательно его оставил (строки Codex, отчёт `AI_CHOREOGRAPHER_CATCHUP_RESEARCH.md`).
- `git stash list` записать. Тайники лежат в `.git` и переедут вместе с папкой.
- `git push` всех нужных веток. Сверить `git log origin/main..main` (должно быть пусто).
- Удалить worktree архивированных сессий Claude (`git worktree remove`) и `git worktree prune`.
- Размер переносимого: `tools\disk_report.ps1`. Свободное место на C: (16.10: 127 ГБ).
- Нет запущенных `cargo`, `rustc`, `grid-app` и `grid`.

### Шаг 2. Перенос — Claude, после «да» владельца

- **Вариант A (рекомендую): перемещение в пределах диска C:.**
  - `Move-Item "C:\Users\debros\OneDrive\Документы\Reassembly" "C:\Dev\Reassembly"`. В пределах одного тома это переименование: мгновенно, жёсткие ссылки сохраняются.
  - Перед этим создать `C:\Dev`. Папка `target\` переедет как есть, удалить её можно позже.
  - **Следствие для облака:** когда синхронизация возобновится, OneDrive увидит, что папка исчезла, и удалит облачную копию. Она попадёт в корзину OneDrive, где хранится около 30 дней.
  - Код при этом остаётся на GitHub. Закрытые данные `local\` в облаке не нужны: это проприетарные материалы, их лучше там не хранить. Если владельцу нужна резервная копия `local\`, её делают отдельно до шага 2.
- **Вариант B: копия с проверкой.**
  - `robocopy` в `C:\Dev\Reassembly` (`/E /COPY:DAT /DCOPY:T`, без `.claude\worktrees` и `target`), затем `dedup_hardlinks.py --apply` на новом месте.
  - Старая папка остаётся нетронутой до шага 8.
  - Нужно на время примерно столько же свободного места, сколько занимает проект, плюс развёрнутые дубли.

### Шаг 3. Git на новом месте — Claude

### Шаг 4. Сборка — Claude

- В `C:\Dev\Reassembly` выполнить `cargo metadata`. Там будет новый `build_directory`.
- Засеять его из старой папки сборки основной копии (`tools\seed_build_dir.ps1 -Source C:\cargo-build\6c\ca670ce8604e98`, если она к тому времени полная) или просто собрать заново.
- Запустить `tools\update_prototype.ps1`. Прототип собирается в `C:\Dev\Reassembly\target\release`, ярлыки работают из новой папки.
- Проверить: `cargo t -- --include-ignored` с абсолютными путями `GRID_*` к `C:\Dev\Reassembly\local\...`, сольные круги, `grid-soak quick`.

### Шаг 6. Claude Code — владелец и Claude

- Claude обновляет путь в плановой задаче отчёта о диске.

- Общая папка заметок сессий `C:\Users\debros\AppData\Roaming\Claude\side-session-notes` не зависит от пути проекта.

### Шаг 7. Запись и уборка — Claude
