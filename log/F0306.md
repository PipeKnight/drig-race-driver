Cause [V code]: in 0x79A530 the angle test is an xz-only f32 cosine; its lengths come from rsqrtps plus one Newton step (0xCAF888 1.0, 0xCAF88C 0.5), which biases |cos| upward. 0xBF4077 acos returns NaN for |x|>1 (0*inf at 0xBF4499, no clamp), and comiss/ja treats NaN as not taken -> return 0 -> not excluded -> Branch A fires. The F302 emulation used a clamped double cosine. Evidence: tools/analyze_avoid_leak.py (sha256 1b847a6f...ff99913c6): all 70 TSV leak rows (the in-run counter said 71) lie within 5.1e-4 rad of antiparallel to the from-gate t; fire rate per 1e-4 rad bin 1.00/1.00/0.89/0.55/0.37/0.04/0; 0 of 19,447 frames beyond 7e-4. tools/avoid_leak_rsqrt_mc.rs (sha256 199c13f1...6f4438c7d, rustc 1.99.0) on the same i7-12700 with host rsqrtps gives 0.99/0.98/0.96/0.87/0.62/0.25/0.03/0, the same sharp edge about 1e-4 rad further out [I: pitch, w lane, sample timing]; exact or truncated rsqrt models do not match. 0x79EE30 order [V]: 0xAB87D0, view refresh 0x79C360, tests 0x79CAA0, controller 0x787620 (driver+0x3100, touches neither view nor records), vtable+8 of *(drv+0x9F8), 0x79E050; so stale data is not the cause.
