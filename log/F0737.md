F737 Race OSD froze after a mid-race window resize: the display material kept the old texture; rebind on resize, render-world bind check, window check tool (2026-11-05, Claude Code).
- Coordinator task, owner playtest of prototype ee26c2ebc427 (F729/F730): "спидометр и карта перестали работать, они остаются статичными" (judder gone: "теперь ощущения рваных кадров нет"). Backlog row 118.
- Cause [V]: not the interpolation. The owner's `menu-20505-18876.log` maximised the race window to 2560 × 1369 after the race had started (line 508; the start is line 449). In the earlier working session the resize came before the race.
  - The OSD image follows the UI camera's size; `osd_scene::resize` resized it under the same handle, which gives a new GPU texture.
  - A Bevy 0.19 `UiMaterial` rebuilds its bind group only when the material asset changes: `PreparedUiMaterial::prepare_asset` binds the texture view and tracks no image dependency.
  - So the screen kept showing the old texture: the whole OSD (dial, speed, gear, needle, timers, position, minimap) stood still as at the resize, while the race went on.
- Reproduced [V], feature build (dlaa, paint-specular) of ee26c2eb: silent autopilot race in a 1280 × 800 window, resized mid-race to 2560 × 1369 by `SetWindowPos` on the game's own window (no activation, no keys).
  - Two shots 2 s apart showed the same race time 0:29.696 and 72 km/h, while the 3D view moved on.
  - A race that starts at 2560 × 1369 updates normally (220 → 217 km/h, 0:24.368 → 0:26.352).
  - Private evidence: `local/judder/hud/rs/`, `big/`.
- Fix [V]: `osd_scene::set_size` also touches the display material (`OsdDisplay`), so its bind group is rebuilt with the resized texture. This is the shared path, and it also covers a phone rotation. The rear-view mirror keeps a fixed-size target; `render_scale` already adds a new image on each change.
- Checks:
  - Render world: `check_display` prints `osd_display bound=B size=WxH` when the binding or the texture size changes. `bound=false` means a stale OSD is on screen.
  - `[diagnostics] window_shots = S,S,...` (`GRID_WINDOW_SHOTS`) saves what the window shows, HUD included, at those real-time seconds. It works in the interactive window only.
  - `tools/hud_window_check.py`: a silent autopilot window run with `GRID_TICK_INTERPOLATION=1` and a mid-race resize. It passes on the last `osd_display` line and keeps the shots.
    - With the rebind disabled (exe a4c8944adc0a): `bound=true 1280x800`, then `bound=false 2544x1330`, so `--expect-stale` PASS.
    - Fixed (exe a236d1a89b5a): `bound=true 2544x1330` PASS. Shots after the resize: 0:34.400 → 0:36.400, 25 → 4 km/h, gear R → 1, the map marker moved (`local/judder/hud/check-fixed/`).
  - Test `a_resize_rebinds_the_display_material_to_the_resized_image`. Targeted `cargo test --release -p grid-app -- osd_scene race_osd race_hud settings`: 38 passed, 2 ignored.
