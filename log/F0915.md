- Reading [I]:
  - F912 step 3 (GPU geometry and shadows) is refuted for now. Removing shadow casters, or every track mesh, cut g_opaque by up to 8 ms and render by up to 7 ms, yet the median FPS stayed at 24-26.
  - Step 2 wins, broadened to fixed CPU cost per frame on both threads:
    - the main thread waits about 30 ms inside schedules for systems on a compute pool that is only 18 % busy;
    - the render thread's `r_encode` is about 12 ms in every state.
  - This looks like a dependency chain of short systems that hop between threads, with wake-up latency at each hop, perhaps landing on the phone's little cores. That is not verified.
- Decision: first implement live Performance test switches that run the main-world and render-world schedules single-threaded (`ExecutorKind::SingleThreaded`).
  - One phone run will show whether the hops cost the frame.
  - Expected gain: 3-10 ms per frame if the waits are hand-off latency, 0 if they are critical-path work. If it gains, the mobile preset makes it the default for every track and car.
  - Later candidates: `frame_split::gpu_begin`'s `device.poll` (about 2 ms on the render thread while the counter shows), and a smaller compute pool.
