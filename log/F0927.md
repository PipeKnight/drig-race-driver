- 2x MSAA panic, fixed in shared code [O]:
  - the first Auto-cycle bench (APK d43c4ef3) panicked at step 11, `mobile:msaa2`: `foundation_backing.rs:80` "source coverage refused unsupported pass" (coordinator's logcat `local/android-logs/2026-11-25-bench/logcat-panic-182623.txt`);
  - cause: the track's alpha-coverage material (`RawMaterial`, used in every normal race) routed 1x to the cheap quarter-coverage path and only exactly 4x to the hardware A2C path, and `expect`ed on anything else. A player's 2x MSAA would crash the same way;
  - fix: every multisampled main pass (2x or 4x) takes the A2C path (`attachment` now needs 2 or more samples); `specialize` never panics: an unknown variant keeps Bevy's stock descriptor and logs `source_coverage unsupported_variant` once. `foundation_front.rs` (diagnostic only) got the same no-panic fallback. `smoke_boundary.rs` already declines non-4x gracefully;
  - new test `msaa2_main_pass_takes_the_same_a2c_coverage_as_msaa4`; the `msaa2` row is back in the cycle (16 steps).
