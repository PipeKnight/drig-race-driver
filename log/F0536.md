F536 Android seed reuse: build_android.ps1 drops MSYSTEM/CYGWIN so cargo-ndk paths match the seed (2026-10-21, Claude Code, checks-and-release; coordinator's follow-up to F534).
- Cause, proven: cargo-ndk 4.1.2 (`src/cargo.rs`, `if env::var("MSYSTEM").is_ok() || env::var("CYGWIN").is_ok()`) rewrites every value of its build environment (CC_/CXX_/AR_<target>, sysroot paths, linker) to forward slashes. Git Bash sets MSYSTEM=MINGW64, and a PowerShell started from it inherits it. Inside a native PowerShell with the same ANDROID_NDK_HOME, `cargo ndk-env -t arm64-v8a --json` gave `C:\\Users\\…\\clang++` with MSYSTEM unset and `C:/Users/…/clang++` with MSYSTEM=MINGW64. `env -u MSYSTEM` in Git Bash does not help (the MSYS runtime sets it again for Windows children).
- android-activity's cc build script tracks those variables (rerun-if-env-changed). The seed (C:\cargo-build\seed, 19.10) recorded backslashes; builds started from Git Bash (the coordinator's 20.10 APK dir 11\021f3a9841e698, the F534 release test) recorded forward slashes. So every fresh seeded build dir reran it and rebuilt android-activity and 33 Bevy/winit crates per APK variant.
- Fix: `tools/build_android.ps1` removes MSYSTEM and CYGWIN from its own process before cargo ndk, so the paths always take the seed's backslash form. The seed needs no rebuild. Build dirs made from Git Bash before this rebuild those crates once more.
- Measured, fresh detached worktree and fresh build dir each, plain APK, launched from Git Bash, release: before (501ff3e4) 1375 s, 38 crates compiled (android-activity, our 4, 33 Bevy/winit); after (this change) 385 s, 4 crates compiled (grid-formats, grid-world, grid-tools, grid-app). Both build dirs (5.45 GiB each) pruned, worktrees removed. Evidence: `local/seedtest-evidence/` in the checks-and-release worktree.
- Not measured: the `-Profile` and `-BundleData` variants after the fix. They use the same cargo-ndk environment, and the profile variant has its own Bevy artifacts in the seed.
- Also `tools/prepush.ps1`: a `tools/` file now escalates to the workspace tier only when Rust code outside comments names it. Before, the comment in crates/grid-app/Cargo.toml that names tools/build_android.ps1 sent this change to the workspace tier, which passed anyway: 872 passed, 0 failed, Clippy clean, 852 s (`local/prepush/f536/`).
