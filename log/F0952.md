F952 Disk audit by owner: tools/disk_audit.py (2026-11-26, Claude Code).
- The owner asked whether Claude or Codex fills the disk, and asked for a permanent script for this recurring question. Added `tools/disk_audit.py` (stdlib, read-only, about 20 s); method and first results are in docs/DISK_USAGE.md section 12.
- It attributes checkouts, their cargo build dirs (via `cargo metadata`), local/, E:/DRIG-local, and the Claude and Codex data folders to claude / codex / shared / orphan. Each run saves a snapshot to `local/disk-audit/` and prints the growth since the previous run plus the bytes written in the last 24 h.
- First run: C: 24.9 GB free. Claude 117.1 GB (42.8 GB written in 24 h, mostly worktree build dirs from the APK and probe series). Codex 106.7 GB (26.0 GB in 24 h; the grid-graphics-delivery worktree is 55.9 GB, ~/.codex/sessions 16.9 GB). Shared 68.4 GB.
- Bugs fixed while testing: subprocess did not find cargo through a changed env PATH, so every build dir showed as orphan; the full path is used now. Deltas are keyed by path, not by label.
- No cleanup was done; deleting needs the owner's word.
