F940 Codex audit reads code-mode exec cells and wait calls (2026-11-26, Claude Code).
- Problem: newer Codex builds run tools in code mode. A top-level `exec` call holds a JavaScript cell that calls `tools.exec_command`, `tools.write_stdin` and others, and `wait` waits for a running cell. `tools/codex_usage_audit.py` (F939) only knew the old names `shell`/`exec_command`/`write_stdin`, so it found no shell calls and reported the observation share as null.
- Change: the script parses the `tools.NAME(...)` calls inside each cell (string-aware parenthesis matching, `cmd`/`workdir`/`chars`/`session_id` literals) and runs the same status-only and empty-write_stdin checks on them. `wait` and `sleep` count as observation calls; new flags `cell_wait`, `repeated_wait_same_cell_within_turn`, `wait_returned_still_running`, `sleep_call`. New keys `inner_tool_calls_by_name`, `top_level_tool_calls`, `top_level_observation_calls`, `observation_share_of_top_level_calls` (a top-level call observes when it is wait/sleep, a status-only command, an empty write_stdin, or a cell whose every inner call is one of those).
- Check (local rollouts since 2026-11-19, roots `~/.codex/worktrees` and the main checkout; process counts only, no spend): 18,941 top-level calls, of which 4,463 only observe (23.6 %): 3,516 `wait` calls, 915 of them repeat a wait on the same cell within a turn and 918 return "still running". Inside cells: 15,092 `exec_command`, 1,887 `write_stdin` (1,739 empty, 765 repeated within a turn). Shell-level observation share 10.3 %. The full output stays outside the repository.
- Interpretation: about one Codex call in four only waits, close to the share measured for Claude sessions in F733. Longer `yield_time_ms` on a single wait, or one blocking wait per job, would remove most of the repeats; AGENTS.md "Codex" already asks for bounded waits.
