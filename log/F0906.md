- Why: the coordinator's brief for the first public desktop release (rows 129-134, F858). This session builds the player build and the Windows package. The Linux sibling builds the tarball and AppImage from this commit (F903); the macOS agent builds the DMG and publishes; the coordinator writes the release notes. Nothing was published on GitHub.
- Row 129, data folder: `settings::choose_data_dir`. Order:
  - `local/` in the current folder, unchanged for developers;
  - otherwise `DRIG-data` beside the program: the exe's folder; on macOS the folder holding `X.app`; on Linux the folder of `$APPIMAGE`. A write probe (`writable`, leaves no file) checks it;
  - otherwise the per-user folder, with the log line `data_dir mode=per-user reason=...`.
  `--data-dir` overrides all of them. No migration (brief); docs/PLAYER_README.md says where earlier builds kept their data.
- Row 132, Cargo feature `dev-tools` (grid-app, default on), so the owner's builds, launchers, APK scripts and prepush keep every tool. The player build is `cargo build --release --locked -p grid-app --bin grid-app --no-default-features`. It differs in these ways:
  - `crate::dev::var` reads every `GRID_*` as unset (130 call sites in 63 files). Exceptions: GRID_GAME_ROOT; GRID_MENU_AUTO, GRID_MENU_LOOPS and GRID_SERIES_EXPERIMENTAL (smoke runs and child processes); the transition.rs hand-off variables.
  - `[diagnostics]` in settings.ini is ignored and counted (`settings_diagnostics ignored=N`).
  - The probe entry points (`--coverage-sample-probe`, `--speech-files`, `--menu-routes`) and `--help-dev` are gone.
  - On Windows it is a GUI program (`desktop_main.rs`, `windows_subsystem = "windows"`), so no console opens. Started without a terminal, stdout and stderr go to `DATA/drig.log`, and the previous run's log is kept as `drig.previous.log`.
  - Not gated: the developer command-line flags still parse when given; the diagnostic modules are compiled in but off by default (CPU lap timers behind the frame split, per-tick log lines). `release_playable.ps1` and the APK scripts still build only the dev variant.
  - `tools/identity.tsv` unchanged.
- Row 134, player flags (`player.rs`):
  - `--game-root`, `--data-dir`;
  - `--fullscreen` / `--windowed`, `--resolution WxH`, `--render-height`, `--quality`;
  - `--race`, `--track ROUTE` (exact route, a path part or a venue; implies `--race`);
  - `--career`, `--list-tracks`, `--skip-intro` (accepted; there is no intro);
  - `--version`, `--help`.
  The window and video flags are an override layer above settings.ini, not saved. `--race` / `--track` press the menu's Continue with the saved or chosen route. Any other flag runs the old developer path unchanged. Listed in `--help` and docs/SETTINGS.md section 6. `--help`, `--version` and `--list-tracks` print only their own text: `mobile::init_threads` is skipped for them, since its `mobile_threads` line came first in the first package's `--version`.

  - `DRIG-v0.1.0-windows-x86_64.exe`;
  - `DRIG-v0.1.0-LICENSES.txt`: the GPL, then LICENSES/{Apache-2.0, Bevy-MIT}.txt and the Fira Mono OFL, each under a heading, so the notices travel with the binary without an archive;
  - `SHA256SUMS.txt` over every release file in the folder (.exe, .txt notices, .gz, .AppImage, .dmg; not itself).
  No .cmd launchers, no dlaa, no game data. docs/PLAYER_README.md is no longer packaged; it is the source of the Windows section of the release notes (put the exe in a writable folder; update by replacing the exe, DRIG-data is shared).

  B logged 636 `transform_burst` lines (transform propagation 3-24 ms). No crate commit lay between the bases, and nothing hot reads `dev::ENABLED`.
- Cause: Windows power throttling (EcoQoS). The player exe is a GUI-subsystem program, and Windows throttles one whose window is not in front. The benchmark windows are not in front while the owner works. Two checks:
  - the same B exe with only its PE subsystem field patched to console ran 17.01 / 16.99 / 16.98 ms mean (p95 17.6), against the unpatched exe at 19.33 / 19.47 / 19.52 (p95 29.2-29.8);
  - the unpatched GUI exe ran 16.99 / 17.00 ms mean (p95 17.6) once the A/B script opted it out of throttling from outside (`SetProcessInformation`, ProcessPowerThrottling, ControlMask EXECUTION_SPEED | IGNORE_TIMER_RESOLUTION, StateMask 0).
- Fix: `player::keep_full_speed()`. At start (not for `--help`, `--version` and `--list-tracks`) the process makes that call for itself and logs `power_throttling off`. It runs in both builds; outside Windows it does nothing. It uses the current-process pseudo-handle (-1), because fixed_ticks.rs and front_end_host.rs already declare `GetCurrentProcess` with another return type.
