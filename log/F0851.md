- Goal (coordinator, after F849): a permanent, cheap record of the worst FixedUpdate tick (tick, per-system times for the whole fixed step, page-fault delta) in the normal perf output, so the next GO spike names its stage.
- Change (`crates/grid-app`): new `fixed_ticks.rs`. At `Plugin::cleanup` every system of `FixedMain` and of each `FixedMainScheduleOrder` schedule is replaced in the schedule graph by a delegating wrapper that adds its run and deferred-command wall time to a slot; Bevy's `run_fixed_main` bounds the tick and reads page faults (Windows `K32GetProcessMemoryInfo`, Unix `getrusage`) and the race tick. Output: `fixed_max_ms` in `frame_stats`; a `fixed_tick_slow` line per tick of 40 ms or more (cap 100) with the 8 slowest systems; `fixed_worst_*` in `perf_timing`. Systems are named `<schedule>/#<index>`; every record and the start line print the build revision, and the start line the system count per schedule.
- Naming decision: release builds have no Bevy system names (`DebugName` shows a placeholder without Bevy's `debug` feature, which grid-app enables only under `profile`; first test run showed `FixedUpdate/<Enablethedebugfeaturetoseethename>`). Coordinator ruled against enabling `debug` in normal builds (Bevy-wide rebuild and seed refresh for a diagnostic). Fallback: a `--features profile` build of the same revision run with `GRID_FIXED_TICK_NAMES=1` prints the index to name table and exits. `libc` moved from the Android-only to the Unix dependency table (already in Cargo.lock).
