F751 Tyre smoke pipelines warmed behind the start cover (2026-11-05, Claude Code).
- Task (owner-approved 2026-11-05, via the coordinator): warm the first tyre smoke's pipelines behind the start cover, so the first smoke of a race builds no pipeline mid-race. F740 had left this open (docs/PIPELINE_WARMUP.md §2.1).
- Before [V] (F740 traces `local/blink115/t2/`, 2560 × 1369, autopilot): Washington and Spa each made 3 pipelines after the warm-up, on the first frame with smoke sprites (render frames 685 and 666): `tyre smoke depth reduction`, `tyre smoke compose` and `pbr_alpha_blend_mesh_pipeline reduced`, 1 frame each.
- Cause [V code]: the source smoke pipelines are warm from the start. The five smoke groups are spawned with an empty mesh, visible and unculled. But the automatic replay (`smoke_boundary/live.rs` `Reduction::prepare`, every window and image view) returned before the reduced buffer (F645) when a frame had no sprites, so the buffer's pipelines were queued on the first smoke.
- Fix (shared path: every car, track, view format and sample count):
  - New `smoke_reduced::queue` queues, once each, the reduction, the composition, and the reduced variant of every source pipeline the replay owns. `prepare` now uses it.
  - The automatic replay calls it on every frame, with or without sprites, so these pipelines compile behind the warm-up cover.
  - A resize changes no pipeline key, so it needs nothing (F742 rebinds a material, not a pipeline).
  - Sprites mode is research-only and is not covered.
- Test `smoke_reduced::tests::pipelines_are_queued_once_before_the_first_smoke` uses a fake queue standing in for the PipelineCache. It checks four things:
  - all three pipelines are queued without sprites;
  - the variant is single-sample with TYRE_SMOKE_REDUCED;
  - a repeat or a resized view adds nothing;
  - an uncovered source keeps the full-size replay.
  The window's own replay path was exercised by the trace runs below.
