- `tools/build_lock.ps1`: one cargo build at a time across checkouts. An OS file handle on `C:\cargo-build\build-lock\lock` (a dead holder never blocks; a stale file is reported and taken over), a FIFO queue with printed position and holder, re-entrant for child scripts (GRID_BUILD_LOCK), `-Status`, and a wrapper for ad-hoc commands (`powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_lock.ps1 cargo …`, exit code passed through). Wired into prepush (per cargo step), update_prototype, build_android (cargo ndk + Gradle), release_playable (per APK) and build_gate (perf phase, up to -PerfWaitMinutes). Tested: two concurrent commands queued and ran in order; a holder killed with taskkill /F was taken over at once; the scratch release's APK build waited 533 s behind a prepush test run, and that prepush's Clippy waited 1329 s behind the APK.
- `tools/release_playable.ps1` (coordinator, main checkout, never pushes): preflight (main checkout, no tracked changes, `git merge-tree` clean, prototype/portable not running, private inputs), merge as the owner with the usual message, update_prototype, optional build gate (`-Gate`), portable exe + changed settings/launchers, both APKs from a temporary detached worktree of origin/main (pruned with prune_build_dirs -ForWorktree, then removed), APK test-order text (names, sizes, time, F range, no-copy lists when the bundle is unchanged), draft log entry in `local/release/<time>.md`. Steps skippable (`-NoMerge`, `-NoPrototype`, `-NoPortable`, `-NoApk`, `-NoProfileApk`, `-NoTestOrder`, `-KeepApkWorktree`, `-DryRun`).
