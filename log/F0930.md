F930 frame_split GPU readback: no slot reuse with a map outstanding (Mac crash) (2026-11-26, Claude Code).
- Fixes the crash found in F929: the owner's Mac run exited 16.5 s into the race with the F9 counter on. `Queue::submit` failed because `frame_split_readback` "is still mapped", then wgpu 29.0.4 `map_async` panicked with "Buffer is already mapped". Cause: `gpu_begin` freed a pending slot without unmapping its buffer, on the map-error path and on the 60-frame timeout path.
- Change in `crates/grid-app/src/frame_split.rs`: the ring is now `GpuInner` with `collect`, `open`, `close` and `start_map`.
  - Each slot has a `map_outstanding` bit. It is set by `map_async` and cleared only by an unmap or a buffer replacement.
  - A slot records again only when the bit is clear. Otherwise the frame records no GPU timings: `open` and `close` skip it, and `start_map` never maps twice.
  - Every map gets a fresh `Arc<AtomicU8>` flag, so a late callback from a map the ring gave up on cannot mark the next map as done.
  - On success the buffer is read and `unmap()`ed. When a map failed (flag 2) or timed out (`MAP_TIMEOUT_FRAMES` = 60), the slot gets a **new** readback buffer instead of an `unmap()` call.
  - Why the buffer is replaced rather than unmapped, a deviation from the F929 proposal: in wgpu 29, `unmap()` on a buffer whose map failed (so not mapped) is a validation error, and Bevy's device error handler turns it into a render error. Dropping the last handle runs `buffer_drop`, which unmaps a mapped buffer or aborts a pending map and ignores the error.
  - frame_stats prints a new `g_lost=` count of slots given up on, after `g_bad`.
- Test `frame_split::tests::readback_slot_is_reused_after_a_timed_out_or_failed_map`. It runs in its own process (`gpu_test_process::in_own_process`) on a real wgpu device and drives `GpuInner` through four rounds:
  1. a normal map and read;
  2. a slot whose map is never polled, given up on after 60 collects, then reused;
  3. a failure forced through the flag, then reused;
  4. a busy slot that skips its frame, then records again.
  - Result: `cargo test --release -p grid-app --bin grid-app -- frame_split::` passed, 5 of 5, in 1.00 s. Log: `local/ab/f930-test.log` in the mac-perf worktree.
  - The Mac path itself is not verified: the PC never hit the timeout. The owner's next Mac run with F9 on will show `g_lost` and whether the race finishes.
