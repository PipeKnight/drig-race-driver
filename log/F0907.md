- Bug found in the release (all platforms): the player start ignores `--game-root`.
  - `drig --game-root PATH` printed `the Menu build failed: GRID was not found in the Steam libraries`. `--list-tracks --game-root PATH` and `GRID_GAME_ROOT` failed the same way. `[game] root = PATH` in DRIG-data/settings.ini worked (`built screen=Menu ok=true`).
  - Cause: `settings::load` never applied the flag. Only the developer parser in main.rs read it, and the menu, career, loading screen, speech and list-tracks starts build their root from `load`. On Windows it matters only when Steam discovery fails.
  - Fix, in the shared settings path: `settings::apply_player_flags` applies the `[video]` overrides of the player flags and `--game-root` (the last one wins) in `load`, after the settings files. `settings::data_dir_flag` reads `--data-dir` (the last one wins). A trailing `--game-root` without a value is an error, like `--settings`. The coordinator moved the v0.1.0 release commit to this fix.
  - `GRID_GAME_ROOT` stays ignored in the player build. That is by design: `dev::var` treats every `GRID_*` variable as unset there (F906). docs/LINUX.md names `[game] root` in settings.ini as the file-based alternative.
- Audit of every player flag that `--help` lists against the player build, start by start (main.rs player dispatch). Menu = `front_end_host::run`. Career = `career_screen::supervise`, which runs the career screen and its races as child processes with `event_menu::passed_on` flags. List = `event_menu::list_routes` via `load`.
  - `--game-root`: now read by `load` on every start. It is also forwarded to children (`passed_on`).
  - `--data-dir`: read by `load` and `setup_output`; forwarded to children. Already correct.
  - `--render-height` and `--quality`: `[video]` overrides in `load`; forwarded to children. Already correct.
  - `--fullscreen`, `--windowed` and `--resolution`: the menu window reads them (`settings::window_preferences`), and the menu's races run inside that window. Correct for the menu.
  - `--race` and `--track`: `set_quick_start` on the menu start. Correct.
  - `--list-tracks`: `list_routes` builds from `load`. With the fix, `--game-root` and `--data-dir` reach it.
  - `--skip-intro`, `--help` and `--version` read no settings.
  - Gap, not fixed here: the career path has no window preference at all. The career screen window is fixed at 1280x800 (career_screen.rs), and its race window uses the render size (main.rs). `passed_on` does not forward the switches. So `--career --fullscreen`, `--career --resolution WxH` and `[video] window` or `resolution` in settings.ini give a 1280x800 window in the career. This is a missing career feature, not a flag parsed only on the developer path. The release notes should say the window flags apply to the menu and its races. The fix belongs in the career's window creation (see Next).
