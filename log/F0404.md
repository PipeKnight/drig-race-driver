- Why [V code]: gilrs-core 0.6.8 has no Android backend (the `bevy_gilrs: Failed to start Gilrs` line stays, harmless). winit 0.30.13 drains GameActivity's input itself: a joystick ACTION_MOVE becomes a fake `Touch` at the stick's AXIS_X/Y, other axes are dropped, pad buttons become unidentified keys. GameActivity 4.4.0 (javap) handles keys in `onKeyDown/Up` and motion in its surface view, so `Activity.dispatchKeyEvent`/`dispatchGenericMotionEvent` see events first.
- `PadBridge.java` (from `MainActivity`): takes key and joystick events of non-virtual SOURCE_GAMEPAD/SOURCE_JOYSTICK devices (so they never reach GameActivity, winit or Android's DPAD/BACK fallbacks; a pad's Back cannot close the game); `InputDeviceListener` plus the device list at `onStart` (only devices with an A button or an X/Y stick are announced before input, AUTHORED guard); `onStop` releases all pads. Right stick Z/RZ, triggers max(LTRIGGER, BRAKE)/max(RTRIGGER, GAS); RX/RY + Z/RZ-triggers heuristic for pads without trigger axes (AUTHORED).
- `android_pad.rs`: platform-independent key/axis mapping (Xbox layout as gilrs; DPAD keys OR hat; L2/R2 keys OR analogue triggers; stick Y negated to Bevy's convention) with 4 desktop unit tests; Android-only JNI natives (`Java_org_reassembly_grid_PadBridge_*`) queue events, a `PreUpdate` system before `InputSystems` writes `GamepadConnectionEvent` and raw button/axis events like bevy_gilrs. The pad then reaches the unchanged input layer: preset 4 for driving, Menu*/Replay* actions for pause, Race Options (Video, Driver Aids, Performance test), post-race and replays; no screen code changed.
- input.rs: `ClassifiedPad` marker (set only by the bridge): with `device=auto` only the wheel guard applies (`not_a_wheel`, split out of `recognised`), so e.g. "8BitDo Pro 2" is accepted. Desktop path unchanged (marker never set there).
- touch_controls.rs: with `device=auto`, a connected `PlayerPad` hides all zones and the tilt bar, ignores touches and silences tilt (`tilt_raw` None); they return on disconnect; fingers down at either change wait until lifted. Log `drive_input_pad takeover=on|off`.
