F920 Performance test: single-threaded executor switches for the main and render worlds (2026-11-24, Claude Code).
- Why: F915 found that the phone's frame is gated by a fixed CPU cost, not by scene or GPU work.
  - The main thread waits about 30 ms per frame inside its schedules.
  - The six compute threads are only about 18 % busy.
  - The test is whether the waits are thread hand-offs (wake-up latency between short systems) or real critical-path work.
- Change (`crates/grid-app/src/perf_test.rs`, `front_end.rs`): two new Performance test rows, live and never saved.
  - "Game systems in parallel" Off (`main_single`) gives the main world's First, PreUpdate, FixedFirst … FixedLast, Update and PostUpdate schedules Bevy 0.19.1's `SingleThreadedExecutor`.
    - `Main`, `FixedMain` and `RunFixedMainLoop` are single-threaded already.
    - The switch runs in `Last`, after `apply`. A running schedule is out of `Schedules`, so the change takes effect from the next frame.
  - "Render systems in parallel" Off (`render_single`) does the same for the render world's Render, RenderGraph, Core3d and Core2d schedules.
    - It runs in the render world's `ExtractSchedule` and reads the switch through `MainWorld`.
  - Turning a row back on restores `MultiThreadedExecutor`.
  - Each change logs `perf_test version=1 event=executor world=main|render single=… schedules=N`.
  - Label: `perf_test=mobile:main_single+render_single`. `GRID_PERF_TEST` accepts `main_single` and `render_single`, and the Auto cycle has a step with both.
  - Parallel queries inside a system (`par_iter`) still use the compute pool.
  - The simulation and the system order are unchanged: the dependency graph is the same, so only the executor changes.
- Tests:
  - `perf_test::main_single_swaps_executors_and_systems_keep_running`: Update and PostUpdate systems keep running after the switch is turned on and off again.
  - `set_executors` finds 1 of 9 labels in a `Schedules` holding only Update.
  - The front-end test toggles the two new rows and checks the label.

  - [I] On the desktop the parallel executor gains nothing over one thread, so the switch costs nothing there either. The phone run decides.
