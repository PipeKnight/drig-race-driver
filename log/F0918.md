F918 Unified per-run logs on all platforms (2026-11-25, Claude Code).
- Owner decision 2026-11-25 ("the same everywhere"): one run-log scheme for Windows, Linux, macOS and Android. The engine now writes it: `player::setup_output` (crates/grid-app/src/player.rs) sends stdout/stderr of a start with no terminal and no redirect to a new `DATA_DIR/playtest/drig-<UTC yyyymmddTHHMMSSZ>-<12-hex revision>.log`, created with `create_new`; same-second starts get `.2.log`, `.3.log`, …; after creating it, only the 10 newest names of exactly this form stay (`run_log path=` / `run_log removed=` lines). `drig.log`, `drig.previous.log`, `time-trial-records.tsv`, `manual-*.log` and the F916 launcher's `drig-STAMP-REV.XXXXXX` files are never matched or deleted. The `dev::ENABLED` early return is gone, so a dev-tools build started from Finder or Explorer also logs; terminal starts and redirects (owner launchers, smoke tools, menu child processes) are unchanged. Windows players move from `DRIG-data\drig.log` to `DRIG-data\playtest\` (release-note line in docs/PLAYER_README.md "Changes since v0.1.0").
- macOS: tools/build_macos.py LAUNCHER no longer redirects or names logs; it resolves the data folder (GRID_DATA_DIR, `DRIG-data` beside the app, per-user fallback) and the game folder, and passes the same `--data-dir` to every launch unless the command line has one. A Finder start has stdout on /dev/null, which `os::detached` counts as detached, so the engine logs it. tools/rebuild_macos.py always sets a 12-character GRID_BUILD_REVISION.
- Android: CrashLog.java names files `<prefix>-<UTC yyyyMMddTHHmmssZ>-<revision>.txt` (log, import, extract) with `BuildConfig.GRID_REVISION` from the GRID_BUILD_REVISION that build_android.ps1 already exports; KEEP=10 per prefix unchanged.
- Linux: tools/package_linux.sh AppRun and the .desktop file exec the binary without a redirect (checked), so the engine's run log applies.
- Docs: README.md, docs/PLAYER_README.md, docs/SETTINGS.md section 6 "Run logs", docs/MACOS.md, docs/ANDROID.md.
