Details: docs/PERFORMANCE.md "Memory growth (F481)". Evidence: worktree trusting-driscoll-f0fd01 `local/leak/` (`guard2.sh`, `bisect*.sh`, `runs/*.mem|out`, `asset_counts_sampler.rs`, `checks-*.log`).
- Symptom (career session): release grid-app on Nürburgring route_1, autopilot and `--drive-ticks`, grew ~9.5–10 MB/s with 20 cars, ~5.7 with 12, also after `drive_script_complete`; 64 GiB unattended, wgpu DeviceLost and a bevy_pbr cluster PoisonError when guarded. Reproduced [V]: 20 cars, frozen after 600 ticks, working set +9.7 MB/s (`runs/base20.mem`).
- Cause [V]: the opponent engines, all tyre voices and the HUD sounds were spawned with `PlaybackSettings::LOOP`. Their decoders never end, but Bevy plays LOOP as rodio 0.22 `repeat_infinite()`, which wraps the source in `Buffered` and keeps the first span to replay from, so every 32 768-sample span (131 072 B) decoded since the start stays reachable. 48 kHz mono f32 = 192 kB/s per source; 19 engines + 20 tyre sets + stereo HUD ≈ 7.9 MB/s heap for 20 cars, ≈ 4.8 MB/s for 12. It runs on audio time, so a finished race kept growing. The player's engine already played once and was not affected.
- Found by: `GRID_ASSET_COUNTS=1` (new, kept: asset/entity counts of both worlds, wgpu resources and GPU allocator total every 600 frames), all flat while the process grew; a temporary counting global allocator showed the Rust heap growing ~55 KB/frame; a temporary sampling heap profiler (every 97th allocation backtraced, freed ones dropped; not committed) put all growing bytes in `rodio::source::buffered::extract` for the three decoders on the cpal thread (`runs/sample1.out`). A subsystem bisect earlier wrongly read the audio-off run as growing (its rate window included loading; it was flat afterwards) — recorded so the method is not trusted blindly.
- Fix: those sources play with `PlaybackSettings::ONCE`, like the player's engine (the sink never empties, nothing is buffered). No cap, no purge. Ignored test `tyre_sound::tests::endless_tyre_voices_play_once`. The collision-impact source of F479 (landed during this work) had the same LOOP on an endless decoder and is changed too; that part is checked by inspection and the short run below, not by the 300 s runs.
