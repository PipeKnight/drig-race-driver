- 60 Hz (block 3) [O]: a 90 s lean run with `-RefreshHz 120` logged `android_frame_cap hz=Some(120.0) result=0` but `display_hz` stayed 60.000004. Read-only dumpsys during the run (our package and the display policy only, `local/android-bench/hz-probe/`):
  - display: the built-in display's `PRIORITY_MIUI_REFRESH_RATE` vote has maxRefreshRate=60, so `primaryRefreshRateRange` and `appRequestRefreshRateRange` are [0 60]; active mode 1 (60 Hz); 120/90/40/30 Hz modes exist; `mUserPreferredModeId=-1`.
  - SurfaceFlinger: `Frame Rate Overrides (setFrameRate): {[uid: <ours> frameRate: 60.00 Hz]}`, `supportsFrameRateOverrideByContent=false`.
  - The app already declares itself a game (manifest `android:appCategory="game"` and `android:isGame="true"` since f97d1871; aapt2 on the probed APK: isGame=true, appCategory=0 = CATEGORY_GAME), so the game category does not lift the vote.
  - [I] The vendor (MIUI/HyperOS) per-app refresh policy votes our app to 60 Hz at a priority above the app's `setFrameRate` hint; a window `preferredDisplayModeId` is also an app vote and would likely lose too (not tried). Only the phone's own settings can lift it (an owner action: the per-app or Game Turbo refresh choice, if offered), which we do not touch. So F927's "120 Hz" runs ran at 60 Hz and say nothing about 120 Hz pacing.
  - [I] Why it matters: FIFO at 60 Hz shows a 34–41 ms frame for 50 ms; at 120 Hz it would show for 41.7 ms, so part of the 33.3–50 ms band and the dips would ease without a faster frame.

- Sustained-performance switch: `[diagnostics] sustained_performance = on` (`GRID_SUSTAINED_PERFORMANCE=1`, off by default) calls `MainActivity.sustainedPerformance()` at start-up: `Window.setSustainedPerformanceMode(true)` on the UI thread and, on API 33+, `GameManager.setGameState(gameplay, interruptible)`. It returns `PowerManager.isSustainedPerformanceModeSupported()` and `GameManager.getGameMode()` for the log line `android_sustained_performance on supported=… game_mode=… game_state=…`. An app cannot set its own game mode. `android_bench.ps1 -Sustained` sets it, and the verdict fails without the line. Settings test `grid_options_follow_the_original` covers the key.
  - Phone answer [O] (profile APK 9b4a62b990e9…, `local/android-bench/soak15-cap30-sustained/`): `android_sustained_performance on supported=false game_mode=0 game_state=gameplay`. So MIUI does not support the sustained performance mode (the window flag is then a no-op), and GameManager reports GAME_MODE_UNSUPPORTED (0) for our app, so the Game Mode API and its interventions are not available either. No `sustained`/GameManager lines in logcat.
