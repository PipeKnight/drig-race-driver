- Persistent pipeline cache, design only (coordinator: no Bevy patch now, the owner can decide later; no code): Bevy 0.19.1 creates pipelines with `cache: None` hard-coded (`render_resource/pipeline_cache.rs` lines 565 render, 623 compute), so it needs a patched `bevy_render` holding one process-wide `wgpu::PipelineCache` used at those two sites. wgpu 29.0.4 has `Features::PIPELINE_CACHE` only on Vulkan (Windows, Linux, Android Vulkan); Metal's `create_pipeline_cache` is a no-op (macOS has its own shader cache), DX12 and GLES are not implemented. wgpu checks the header (magic, ABI, backend, adapter key, driver UUID): outdated, corrupt or truncated data with `fallback: true` gives an empty cache, but a device mismatch is an error, so the file name must carry `wgpu::util::pipeline_cache_key(adapter_info)`. There is no payload checksum: add our own hash and length, write via a temporary file and rename. Bevy requests all adapter features by default (`renderer/mod.rs:301`). Cost: a `[patch]` section, seed refresh, Android seed rebuild and a full-tier prepush; it shortens only the cover on a new executable (5-10 s cold vs 2-3 s warm, F848), not the frame rate.
