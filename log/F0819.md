F819 Loading reflection box space (static evidence) (2026-11-10, Claude Code).
- Task: coordinator item 1 after F813: trace how fe3d_tracksurface's caller fills the reflection box and which position the shader receives, looking for a world-to-box transform or a camera-relative space. Static analysis only; grid.exe was not run. Details are in docs/FRONT_END_FLOW.md §2, "Cube reflection".
- Findings:
  - [D] The constant builder 0x4DFC00 (0x4E031F–0x4E0393) only inserts w into `_refMinGamma` and `_refMaxScale` (r_gamma and r_scale, through andps/orps masks). The box xyz go to the shader as the vector reader 0x4C9A70 stored them. The uniform-name table 0xDAB000 (14 names, registered by 0x4D0960) has no box transform.
  - [D] The pixel program declares `float3 EyePositionWS` (c0). The vertex program `vp_instanced` writes the position as Model (c4–c7) × instance rows (v3–v5) × pos, and the normal through the instance rows only.
  - [D] The `loading` group's r_min/r_max, with the same "valueX - max X" comment, are a verbatim copy of `garage_01`'s. garage_02 and garage_03 each have their own box, also car-sized and around the origin.
  - [D] `loading_root` in fePersistentDatabase.pssg: logo_plane and tarmac_plane lie at y −120.34; load_cam's target is at (−44.25, −54.22, −17.12); the screens lie at x −160…−105. Measured with a scratch PSSG extent script over `tools/survey_pssg_payloads.py` (NEANIMKEYS treated as data); the output is not kept.
  - [D] The only code that names `Model`/`ModelViewProj` is 0xB0B600. It sets them from the object's own matrices on a separate draw path. [I] The general mesh path binds the same names through the program's parameter list; this was not traced.
- Conclusion [I, strong]: no world-to-box or camera-relative transform exists on the path that static analysis reaches. V = EyePositionWS − pos makes sense only with world-space positions, and the loading world reuses a garage box that does not enclose it. So the hard-edged floor quad is the original's own result, and the port keeps the formula unchanged. Only a grid.exe capture of the loading screen would close the remaining [I]. Nothing was ported, so there is no image pair.
- Symbols: new rows 0x00B0B600 FeModelMatrixDraw [I] and 0x00DAB000 fe_material_uniform_names [D]. 0x4DFC00 and 0x4D0960 keep HUD's names.
