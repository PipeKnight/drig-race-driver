F836 Frame split in frame_stats for the Mac performance log (2026-11-17, Claude Code).
- Goal (owner, 2026-11-17): excellent performance on the owner's Mac; measure first. Phase 1 (this entry): one owner log must split the frame. Phase 2 (optimisations) waits for the owner's Mac log.
- `crates/grid-app/src/frame_split.rs` appends to the periodic `frame_stats` line (fps counter shown; Video → FPS counter or F9). Fields and meanings: docs/PERFORMANCE.md "Frame split (F836)".
  - Main thread: `main_ms` (First..Last), `fixed_ms` (simulation ticks), `outside_ms` (rest of the frame, incl. waiting for the render thread), `extract_ms`.
  - Render thread, summing to `render_ms`: `r_meshes` (extract commands, asset uploads, specialisation), `r_views`, `acquire`, `r_queue`, `r_sort`, `r_prepare`, `r_bind`, `r_encode` (render-graph encoding), `r_submit`, `r_present`, `r_cleanup`.
  - GPU via timestamp markers (empty compute passes, need only `TIMESTAMP_QUERY`; shadow cascades via pass descriptor timestamps): `gpu_ms`, `g_pre`, `g_shadow`, `g_opaque`, `g_transp`, `g_post`, `g_ui`, `g_upscale`, `g_gap`, `g_frames`, `g_bad`; every tenth window `frame_gpu_views` lines per camera with `shadow_cN`.
  - Counts: phase items per pass `d_opaque d_alpha d_shadow d_transp d_ui`, `shadow_views`, `vis`, `casters`, `views3d`; uploads `mesh_up_s mesh_kb_s img_up_s img_kb_s`.
  - Start line `frame_split version=1 backend= adapter= timestamp_query= inside_encoders= inside_passes= gpu_markers=on|off reason= near_present_marker=`. No feature: `gpu_markers=off reason=...`, `gpu=off` in frame_stats, CPU split unchanged. `GRID_FRAME_GPU=0` turns the markers off; they run only while the counter is shown.
- Metal: Bevy's `RenderDiagnosticsPlugin` times passes with `TIMESTAMP_QUERY_INSIDE_PASSES`, which Metal lacks, and Bevy skips encoder timestamps near present on macOS (bevy#22257). So it gives no GPU pass times on the Mac. The frame split uses no inside-pass timestamps and on macOS leaves out the markers after the last pass (`near_present_marker=false`): there `g_upscale` and the frame tail are not measured. Not yet run on a Mac.
- `gpu_passes::install_shadow_span` (idempotent): Bevy's early shadow pass is now always replaced by the timed one (before: only with `GRID_GPU_PASSES`); it gets the cascades' descriptor timestamps when the markers run. Same passes and order, no image change intended.
- `wgpu =29.0.4` is now a direct grid-app dependency (Cargo.lock), for the query set types.
- Interactive test: `tools/frame_split_smoke.ps1` runs the release build in a normal window (autopilot, fps on, sound 0, `[video] render_height = 720` by default, i.e. the scaled-image path the Mac uses; `-RenderHeight native` for the direct path), stops 2 s after `drive_script_complete`, and checks: start line; every driving window has all fields; `main_ms + outside_ms` = `avg_ms` (±max(0.5 ms, 10 %)); render stages sum to `render_ms` (±2 %); `render_ms` ≤ frame; with markers `gpu=on`, `g_bad = 0`, a 3D view line with cascades, and on the scaled path a timed 2D display line.
