F724 Facing trees keep their expanded bounds; no culling at the screen edge (2026-11-03, Claude (session fervent-napier); Coordinator relayed owner report (2026-11-03, prototype 170678e6ce36): trees vanish while still visible as they approach the screen edge; find the cause, fix it in the shared path, backlog row 112).
- Cause [O]: forest foliage (`trees/facing/`, `trees/sheet/`, `trees/card/`) keeps collapsed quad centres in its mesh asset; `source_trees::present` expands the quads on the CPU each frame. The spawn gave these entities an Aabb grown by `FacingSource::radius()`, but Bevy 0.19 `calculate_bounds` recomputes the Aabb from the mesh asset on every `Changed<Mesh3d>` (the spawn itself, and every ornament fade, since `ornament_lod::respecialize_ranged` marks `Mesh3d` changed when a `VisibilityRange` is added or removed). The bounds then covered only the centres, so a tree was frustum-culled as soon as its quad centres left the view while its leaves were still on screen.
- Fix: `main.rs` inserts `NoAutoAabb` with the expanded bounds on every facing, sheet and card entity (all tracks, presets and Android share this spawn path). The radius is in the instance's local units (offsets are scaled by the instance scale and rotated back by its inverse), so the local box covers the drawn quads exactly to the farthest offset.
- Original [O/I]: the ornament pass culls and selects levels per instance from its world AABB (instance +0x20, the prototype bounds through the placement matrix, docs/TRACK_LOD.md 3.1); that box covers the whole authored tree, not the vertex centres. [I] The vis query uses the same box; its frustum test is not traced.
