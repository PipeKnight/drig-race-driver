- Cause [D]: the original never lets a piece break a prop. `0x7C46A0` (the prop contact callback) only calls the break check `0x7BDFD0` when the two shapes pair like `B0EE80`'s threshold rule: `A.0x228 || B.0x228 || (A.0x17 && B.0x18) || (B.0x17 && A.0x18)` (`0xA6A3D0`/`0xA6A3F0`/`0xA6A410` read registration+8 -> shape bytes 0x228/0x17/0x18). Entity shapes (`0x7C6350`: `0x469A80` zeroes descriptor +4/+5/+6, `0x7B9390` sets +5 and clears +0x60) have 0x17 = 0, 0x18 = 1, 0x228 = 0; car shapes (`car_box` 0xA01960: 0xA01C94, 0xA026BD, 0xA02816) set descriptor +4 = 1, i.e. 0x17. So car-prop contacts carry the threshold and can break; piece-prop and prop-prop contacts carry FLT_MAX and never call the break check. The port gave a piece's contact with an intact box the box's threshold as its limit and recorded it for break detection, so a resting tyre (about 250 N solved) broke every stack it leaned on: the chain cascade.
- Fix: `PropWorld::contacts` (crates/grid-tools/src/dynamic_props.rs) writes FLT_MAX to +0x3C for piece contacts with route props and no longer records them; the `recorded` parameter is gone (callers in source_vehicle.rs and source_vehicle/multi.rs). Car contacts are unchanged. Docs: DYNAMIC_PROPS_RESEARCH.md "Break mechanism" items 1 and 2 (the old [I] note is now [D]); docs/re/symbols.tsv 0x7C46A0, 0xA6A3D0, 0xA6A3F0, 0xA6A410.
