F632 grid-app compute pool with 64 MiB thread stacks (nested drive_tick overflow in parallel tests) (2026-10-28, Claude Code, camera session; coordinator's go: "fix from you, in one commit after F631").
- Symptom: full prepush gates of F630 and F631 (and multithreading's) stopped in the grid-app test binary with STATUS_STACK_OVERFLOW in a `TaskPool` thread. It happened in 2 of 4 full runs, both under extra load from stray Washington grid-app runs. Serial (323/323) and two 4-thread runs (325/325) on a quiet machine passed.
- Diagnosis [V]:
  - A serial run with RUST_MIN_STACK=512 KB overflows in a TaskPool thread during `driving_tests::body_geometry_keyboard_pause_reset_and_failure_recovery`, which loads no cockpit. Its systems are input, pause menu, `drive_actions` and `drive_tick`.
  - Run alone, the three keyboard-recovery tests pass at 768 KB, 1, 1.5 and 2 MB, so one `drive_tick` needs 0.5–0.75 MB.
- Cause [I]:
  - `drive_tick` runs on Bevy's ComputeTaskPool. grid-app let Bevy create that pool with default 2 MB stacks; only `grid_tools::parallel::pool` (headless tools) sets 64 MiB.
  - Since P12 (9adc1b24, 2026-10-18) the simulation's per-car stages call `parallel::map`, a scope on the same pool. A thread waiting in such a scope runs other queued tasks on its own stack.
  - Under parallel test load those tasks are other Apps' `drive_tick`s, so stacks nest past 2 MB. The cause predates F630; the cockpit code is not involved.
- Fix (`mobile.rs`):
  - `init_threads` (first thing in `main`, desktop and Android) now always creates the compute pool, with `COMPUTE_STACK` = 64 MiB.
  - Thread counts are unchanged: Bevy's default split (`bevy_compute_threads`: a quarter each, 1..=4, for IO and async compute, the rest compute) without the preset, `compute_threads` with it.
  - Tests call `init_test_pool` (every core, as an App's executor would create, with the same stack) before each test App: the driving tests in main.rs, `race_app_with`, engine_sound, scene_probe, source_trees, tyre_sound and ui_font.
  - The first pool of a test process stays, so a test App created elsewhere first would still get 2 MB [I: all test Apps now call it].
  - The 64 MiB is reserved address space, committed only as used, on Windows and on Android arm64 too (64-bit address space; each compute thread reserves 64 MiB and commits only the pages its deepest nesting touches).
- Test: `mobile::tests::bevy_compute_threads_match_the_task_pool_plugin` (1, 4, 8, 20 and 32 cores → 1, 2, 4, 12, 24).
- Checks: `cargo clippy --release -p grid-app --all-targets -- -D warnings` clean. `prepush: tier crate [grid-app]`: sanity pass; clippy-crates pass; test-grid-app pass (326 passed, 0 failed, with --include-ignored); `prepush: passed, tier crate, 310 s` (`local/prepush/20261028-005906/`).
