- Change (crates/grid-app):
  - `main.rs` `cap_catch_up` sets `Time<Virtual>::set_max_delta(4 × fixed timestep)` = 64 ms; Bevy's default was 250 ms, about 15.6 ticks per frame. Log line `frame_catch_up max_ticks_per_frame=4 max_delta_ms=64.0`.
  - Only when `interactive = !headless && output.is_none()`. Android starts through the same `main`, so the phone gets it too.
  - Unchanged: `--headless`, `--render` captures (render_fixed_step, render_fps), the test apps, grid-soak, grid-opponent-race and the identity runs.
  - New diagnostics (docs/SETTINGS.md): `max_ticks_per_frame` / `GRID_MAX_TICKS_PER_FRAME` (0 = Bevy's clamp, for comparisons) and `tick_delay_ms` / `GRID_TICK_DELAY_MS` (forced slow tick, a sleep in `drive_tick`). The settings test covers both keys.
- Nothing else depended on the 250 ms default [O]:
  - menus, HUD, pause menu, results, touch, engine sound and the frame counter use `Time<Real>`; presentation uses `Time<Fixed>::overstep`; pause is `Driving::paused`;

  - a long frame after a load or an Android resume now runs at most 4 ticks instead of 15, so the tick-based countdown can skip less than before.
