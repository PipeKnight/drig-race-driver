F543 Physics steps per rendered frame: original one step of the frame delta, port catch-up, no port (2026-10-21, Claude Code, session modest-visvesvaraya; coordinator's task: research and, if confirmed, port how the original steps physics per rendered frame).
- Research in docs/FRAME_STEPPING.md. Static analysis only, through the shared master project with `tools/re/grid_re.py decompile`/`dis`/`xrefs`. The original was not launched.
- Original [O]:
  - Physics task `5E7F30` (vtable `CE34EC`, slot 1 `run(double*)`) passes the f32 frame delta unchanged to the car manager `A02B70`, then to the world scheduler `A72930`.
  - Re-decompiled `A72930`; it matches WORLD_STEPPING_RESEARCH.md.
  - With the live F285 values (maxfps 10000, minfps 0, maxTimesToRun 1), every frame longer than 0.1 ms gets exactly one world step of the real frame dt. There are no extra steps and no upper clamp at this level.
  - Inside the step, the wheel/tyre job substeps `max(1, trunc(dt*999.99994))` times by `dt/n` (VEHICLE_UPDATE.md). The world solver takes the single step.
- Not found: the frame dispatcher that computes the delta, so whether a long frame is clamped is open.
  - Tasks are 0x28-byte records (`87E2D0` every frame, `87E250` fixed period); the scheduler sits at game object +0x20 (`632B10`, `5EB6A0`).
  - Clocks: `B95CC0`, `A6BBF0`. The `A3F3B0`/`C457D0` stopwatches are networking; `9C0F70` is the UDP motion-platform output.
- Port [O]:
  - Interactive grid-app runs every simulation system in `FixedUpdate` at `DELTA` 0.016 s.
  - Nothing sets `Time<Virtual>::max_delta`, so Bevy 0.19.1's 250 ms default applies, and a frame runs `floor(acc/16 ms)` ticks, up to about 15.
  - Headless, `render_fixed_step` captures and the test apps use `ManualDuration(DELTA)`: one tick per frame. grid-soak, grid-opponent-race and the identity runs call `Runtime::tick` directly.
- [D] Model of the F540 collapse: once a tick costs more than 16 ms, the 250 ms clamp binds and every frame runs about 15.6 ticks. 292 ms frames at 53 ticks/s means about 17–18 ms per tick with 220 resting pieces. The original would draw about 36 FPS with r 10 ms and c 18 ms.
- Not ported: this is the brief's stop condition.
  - The original's step is variable. The port uses `DELTA` in 40 source files: solver parameter, deformation, lap time, AI and event timers counted in ticks.
  - F285 showed the drive depends on step size, and F286 (owner) kept the fixed step.
