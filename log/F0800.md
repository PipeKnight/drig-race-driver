F800 cargo td for every package through the build lock (2026-11-10, Claude Code).
- Coordinator task: make `cargo td -p grid-app` work through the build lock again ("--lib cannot be used multiple times").
- Two causes, both fixed:
  - **Alias doubling in worktrees [O].** A worktree reads the main checkout's `.cargo/config.toml` too, and cargo concatenates the two array aliases (`test --lib --test * test --lib --test *`). `tools/build_lock.ps1` now expands a `t`/`td`-style array alias from its own checkout's `.cargo/config.toml` (`Expand-CargoAlias`) before it calls cargo. The queue line then shows the expanded command (`cargo test --tests -p grid-app`).
  - **`--test "*"` with no integration tests [O].** With the doubling gone, cargo stopped with "no test target matches pattern `*` in `grid-app` package": grid-app's tests are in its binary, and a glob that matches nothing is an error. So `td` never worked for grid-app. `td` is now `test --tests`: every target with a test harness (library, binaries, integration tests), with no error for a package without integration tests. `t` is unchanged; its `--workspace` run always has grid-formats' integration tests.
- Docs: docs/TOOLCHAIN.md "Build and test cost" (alias and P9 paragraphs).
- Check: `tools/build_lock.ps1 cargo td -p grid-app`, which showed the doubling error before, now passes: 697 passed, 0 failed, 131 ignored (dev profile; the grid_android library has 0 tests).
- The main checkout keeps the old `td` until a release merges. A plain `cargo td` in a worktree, outside the lock, still doubles the alias; use the lock or spell the command out.
